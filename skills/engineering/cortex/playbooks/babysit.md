### Babysit

**You own the merge frontier. Declare a mode, clear one PR at a time, stop where the human's call begins. You do not merge.**

Babysitting starts when the user asks for it, normally once a phase or a whole stack is built, not when a PR opens. An owner's brief in [Autopilot full](autopilot-full.md), [Autopilot stack](autopilot-stack.md), or [Orchestrate](orchestrate.md) is that ask. A request to land or ship is [Shipping](shipping.md), which begins where this playbook ends.

1. **Read and follow [`babysit`](../../babysit/SKILL.md) in full.** It holds the watcher commands, the verdict table, and the stop conditions.
2. **Declare the mode and resolve the forge before any poll.** `drive` for "babysit this", "get it green", "merge-ready". `background` for a plan still executing. `threads-only` for "address the bugbot comments". `check` for "check on X", "is it green", "anything outstanding on X". Undeclared defaults to `drive`. Small or docs-only PRs get `check`, not `drive`. A phase agent never reaches for `drive`, because the loop stops that agent finishing its turn.
3. **Work the merge frontier and nothing above it.** One babysitter per stack. Never mutate stack topology. Report rebase-shaped work to the PR's owner. An owner babysitting its own PR is that owner. It rebases its own branch and pushes with `--force-with-lease`, per step 2 of [Autopilot full](autopilot-full.md). The one sanctioned creation is a follow-up PR on top of the remaining stack when a fix's owning PR has already merged.
4. **Order is conflicts, then review threads, then CI.** Batch every known fix into one push wave. Do not resolve a conflict. Report it, name the branch that needs the rebase and the drift sweep, then stop. Classify CI before any retrigger. Flake earns one fresh build, never a job retry.
5. **Trust the active forge's verdict, not a green check list.** Ready means the forge agrees the PR can merge. On GitHub, run the skill's `watch-pr` by absolute path, in the target repo's checkout, and act on its verdicts. In a queued stack, pass the same frozen `--stack-prs` list to every rearm. Stop at the skill's forge-specific stop condition. Rearm after every push wave and every verdict you act on. Never add a second sleep loop.
6. **Triage bot review skeptically** per [BUGBOT-TRIAGE.md](../../babysit/BUGBOT-TRIAGE.md). Fix real findings with a red-first proof in the lowest PR that owns the code. Dismiss noise with a concrete disproof. Count bot passes (the watcher's `bugbotReviewPasses` on GitHub, the review history elsewhere). From the third pass on, lean toward dismissing documented patterns, and still escalate security, auth, billing, data, or migrations. Human review voice stays with [`pr-comments`](../../pr-comments/SKILL.md), through [`workshop-findings`](../../workshop-findings/SKILL.md) when the fixes need deciding first.
7. **Stop at the human's line.** Owner approval is a wait, not a blocker to fix. Babysitting never authorizes merging. Route a request to land, ship, or merge to [Shipping](shipping.md). After the stop, sweep the run's triage decisions once and offer any team-useful dismissal pattern as a [BUGBOT-TRIAGE.md](../../babysit/BUGBOT-TRIAGE.md) entry in its own PR.

**Reply:** mode, forge, frontier PR, the last watcher verdict on GitHub, open blockers and escalations, merge-ready or not.
