### Bug fix

**You own the defect loop. Plan, review, verify.** Delegate investigation and the fix to subagents, and stay in the lead. Pick each subagent's model for the job per [cortex's Subagents section](../SKILL.md#subagents). Pick each subagent's reasoning effort for the job when the runtime offers a choice.

Be scientific. Every shipped line traces to runtime evidence. Belt-and-suspenders that "might help" is a hypothesis, not a fix. It does not ship. When evidence refutes a hypothesis, revert what it motivated. The smallest change the evidence justifies ships, nothing more.

1. **Load the loop.** Read and follow [`fix-bug`](../../fix-bug/SKILL.md) in full. Steps 2 to 8 below cover its whole loop and add cortex's gates. They keep its rule that the failing check fails before any production edit. Its failing-then-passing history splits in two: the failing check is step 4 and the commit staging is step 8. Copy these steps into the todolist once, in place of fix-bug's own list.
2. **Reproduce it yourself** on the matching surface, through the repo's `verify-*` skill when it has one ([cortex's Non-negotiables](../SKILL.md#non-negotiables)). Do this even when a debug or instrumentation protocol says to ask the user to reproduce. Ask the user only with a stated, specific reason the surface cannot reach the target, and only after driving it as far as it goes. If it won't reproduce directly, synthesize the trigger, tighten conditions, or instrument until it fires. Capture the failing output, logs, or screenshots you can paste later.
3. **Binary-search the cause.** Form the candidate hypotheses, then rule them out until one survives. Seed them by reading and following [`how`](../../how/SKILL.md) over the affected subsystem and [`why`](../../why/SKILL.md) for regression history. Each pass, take the split that cuts the most remaining problem space, get runtime evidence, and eliminate. When program state is unclear, add instrumentation or logging and read it as the code runs. Don't guess. Drive a long or stubborn hunt as an [Autonomous run](autonomous-run.md). Confirm the surviving mechanism with runtime evidence before the step 5 architect or interrogate fan-out.
4. **Make the failure executable before the fix.** Write the failing test from fix-bug's failing-then-passing history step, yourself or through a delegate, before anyone edits production code. Run it and confirm it fails for the intended reason. If it passes, or fails for an unrelated reason, correct the test or the repro first. Capture that output. When a new test would be expensive, integration-heavy, or unclear, skip it per fix-bug. Run the closest executable check before the fix the same way. The step 2 same-surface capture still carries the failing-before proof.
5. **Plan the fix.** If it crosses a function boundary, read and follow [`architect`](../../architect/SKILL.md) first. Skip it for mechanical work whose shape is already concrete. Delegate implementation to a subagent with a specific scope: the file paths, the confirmed mechanism, the step 4 check that must turn green with its captured failure, and fix-bug's Test guardrails verbatim. The delegate edits production code to turn that check green and never edits the check to fit the code. A cross-cutting or subtle fix goes to the strongest judgment model. A mechanical one goes to a fast model. Review the diff yourself. If the fix is contested or hard to reverse, read and follow [`interrogate`](../../interrogate/SKILL.md) before Opening a PR.
6. **Apply the principles when they fire.** Read and follow [`principle-prove-it-works`](../../principle-prove-it-works/SKILL.md) with [`principle-laziness-protocol`](../../principle-laziness-protocol/SKILL.md). Together they hold the fix to the smallest change the evidence justifies. When two fixes that share one premise fail the same gate, read and follow [`principle-attack-the-premise`](../../principle-attack-the-premise/SKILL.md). Do not invent a parallel defect method here.
7. **Verify on the same surface.** The original repro now passes, and so does the step 4 check. "Inconclusive" or wrong-surface is not a pass. Flag it. Unit tests show branch behavior, not bug absence.
8. **Stage the commits so the failing check lands before the fix** in git history, and a reviewer can replay the failure and then the fix. This is the canonical [`principle-sequence-verifiable-units`](../../principle-sequence-verifiable-units/SKILL.md) shape, the failing test first and the fix on top.
9. Run [Opening a PR](opening-a-pr.md).

**Reply:** what was broken, root cause, fix, how you verified. Name the failing-before check and the failure it produced. Paste failing-then-passing repro output verbatim.
