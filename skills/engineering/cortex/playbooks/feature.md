### Feature

**You own design and delivery. Plan, review, verify.** Delegate implementation. Stay in the lead. Prefer existing decide and explore skills. This playbook owns ground, design, implement, verify, and PR.

1. **Ground.** Read and follow [`how`](../../how/SKILL.md) over the affected subsystem. Also read and follow [`why`](../../why/SKILL.md) when history likely explains the shape or the change moves ownership.
2. **Data shape first.** Name the data shape and choose its organizing structure before any branching logic, per [`principle-model-the-domain`](../../principle-model-the-domain/SKILL.md).
3. **Design.** When the change crosses a function boundary or moves ownership or layering, read and follow [`architect`](../../architect/SKILL.md) for parallel design exploration. It runs [`arena`](../../arena/SKILL.md) over at least two distinct shapes. Skip it for mechanical work whose shape is already concrete. Decide when stuck. For a contested product tree, read and follow [`grill-me`](../../../productivity/grill-me/SKILL.md). For a durable spec, read and follow [`write-rfc`](../../../productivity/write-rfc/SKILL.md). For a tracked unit of work, read and follow [`to-issue`](../../../productivity/to-issue/SKILL.md). For an empirical fork, run the [Prototype](prototype.md) playbook first.
4. **Throughput checkpoint.** Write it as four todo items. A dimension that genuinely does not apply (single file, no fan-out) keeps its item with `n/a: <reason>` instead of being dropped.
   - **Blocking first steps.** Gates run before fan-out.
   - **Independent workstreams.** Disjoint files, services, or layers parallelize. Shared writes serialize.
   - **Shared mutable state.** Default to splitting the target, per [`principle-separate-before-serializing-shared-state`](../../principle-separate-before-serializing-shared-state/SKILL.md). Serialize only for a real invariant.
   - **Smallest safe decomposition.** If one worker is best, name why.
5. **Implement** the smallest change that meets the goal. Delegate code-writing to a subagent per [cortex's Subagents section](../SKILL.md#subagents). The hardest changes (cross-cutting design, concurrency, subtle algorithms) go to the strongest judgment model. Mechanical edits go to a fast model. Pick each subagent's reasoning effort for the job when the runtime offers a choice. Give the delegate a specific scope: the file paths, the named data shape and its organizing structure (a state machine over scattered booleans, a table or registry over branching, a typed model over repeated shape assumptions), chosen before it writes logic, and the success criteria.
   - **Delegation is mandatory.** This step has no `skip: <reason>` escape, and [`principle-laziness-protocol`](../../principle-laziness-protocol/SKILL.md) does not override it. The gain is review separation, not lines saved. A subagent that cannot spawn its own subagents satisfies this step by owning the diff directly, with the same review separation. Never reply "standing by" while you wait on a nested agent.
   - **Shape alternatives.** When [`architect`](../../architect/SKILL.md) ran, implement against its sketch (architect phase D) without another arena. Only when architect was skipped and the implementation admits several valid shapes (error handling, abstraction layer, test structure), read and follow [`arena`](../../arena/SKILL.md) to delegate, so the runners surface the alternatives and the judge guards the pick.
   - **Edits.** Write comments clean as you go. Keep a comment only for a non-obvious why the code cannot show. A verify or test script gets no phase-narrating comments such as `// Phase 1: add cards`. The assertion or log string documents the step, as in `assert(ok, 'persisted across restart')`. This holds for every file you produce, including the delegate's diff. Before review, step 4 of [Opening a PR](opening-a-pr.md) still has you read and follow [`no-comments`](../../no-comments/SKILL.md) on the scoped diff. Make surgical edits. For a file derived from an upstream source, re-ground each edit against that source. Port an improvement to a shared primitive to every consumer, and verify each one. Commit liberally. Review every diff yourself.
6. **Verify** on the matching surface, the one the user hits, through the repo's `verify-*` skill when it has one. Inconclusive or wrong-surface is not a pass. Flag it.
7. **Rebase into small, ordered commits.** Stack follow-ups. Build, verify, and commit each small unit before the next, per [`principle-sequence-verifiable-units`](../../principle-sequence-verifiable-units/SKILL.md). Each unit's check runs on the real artifact, per [`principle-prove-it-works`](../../principle-prove-it-works/SKILL.md).
8. If the design is contested or hard to reverse, read and follow [`interrogate`](../../interrogate/SKILL.md) before shipping.
9. Run [Opening a PR](opening-a-pr.md).

Code-coupled work (one feature, one migration) goes to a single owner subagent, with the throughput checkpoint inline in its brief. That owner fans out internally after the blocking phase. Parent-level fan-out is for slices that produce independent artifacts (audits, cross-subsystem investigations, competing experiments). Rewrite the checkpoint at each phase boundary. Spawn a fresh owner instead of chaining interrupts.

**Reply:** what you built, the data shape and design chosen and why (alternatives as a table), the throughput checkpoint, how you verified, open decisions.
