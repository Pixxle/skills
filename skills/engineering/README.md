# Engineering

Daily code work.

- [architect](architect/SKILL.md) — ground with how and why, sketch usage, types, and module boundaries through an arena of at least two distinct designs, then implement against the sketch and scrap it when friction shows the shape is wrong.
- [arena](arena/SKILL.md) — run N parallel candidates on one brief, each in its own git worktree, then pick a base, graft the strongest parts of the others, and verify.
- [babysit](babysit/SKILL.md) — own the merge frontier until merge-ready: declare a mode (`drive` / `background` / `threads-only` / `check`), drive the GitHub loop on the verdicts of its bundled `watch-pr` script, classify CI flakes, and triage bot review skeptically without merging.
- [benchmark-checklist](benchmark-checklist/SKILL.md) — vet a performance number before reporting or acting on it: limiter, tuning, physical limits, errors, repeatability, end-to-end relevance, and whether the work ran.
- [bump-deps](bump-deps/SKILL.md) — safely upgrade packages, runtimes, and Docker base images one at a time on a fresh branch, validating after each.
- [changelog](changelog/SKILL.md) — generate a user-facing changelog from a commit range and flag every breaking API change a merged PR introduced, with before/after and migration steps.
- [correct](correct/SKILL.md) — find the mistake classes agents keep repeating in a repo and make each impossible (architecture, then types or a lint, then a test, docs last), prove each check fails on a real past mistake, and keep a rule-to-enforcer table in CLAUDE.md or AGENTS.md.
- [cortex](cortex/SKILL.md) — engineering meta-router: restate the goal, match a playbook, copy its steps into a todolist, apply session gates, and load each routed skill by reading its linked SKILL.md.
- [create-system-map](create-system-map/SKILL.md) — explain an unfamiliar repository's capabilities, APIs, construction, data, and end-to-end flows in `_system-map/`, with diagrams and hierarchical sub-agent exploration for large systems.
- [create-verification-skill](create-verification-skill/SKILL.md) — generate a committed project-local `verify-<app>` skill (canonical in `.agents/skills/`, symlinked from `.claude/skills/`) with Launch, Doctor, Drive, Evidence, Cleanup, and Helpers for web, CLI, API, iOS simulator, and Android emulator, plus a feature map, proven end to end before hand-off.
- [figure-it-out](figure-it-out/SKILL.md) — design and run a bespoke, auditable playbook when no cortex playbook fits: falsifiable done predicate, rigor scaled to stakes, keep-or-revert loop per unit, and a handoff decision trail.
- [fix-bug](fix-bug/SKILL.md) — reproduce-first defect loop with TDD rules: same-surface repro, hypothesis binary-search with live evidence, a check that fails for the intended reason before any production edit, the smallest justified fix, the same check passing, same-surface verify.
- [handoff](handoff/SKILL.md) — persist work across agents and sessions: handoff docs, pause/resume notes, pickup from a prior trail, and append-only decision trails.
- [how](how/SKILL.md) — explain how code works today, in chat and read-only: one explainer for narrow questions, or 2 to 4 parallel explorers then one explainer for a subsystem (Overview, Key concepts, How it works, Where things live, Gotchas).
- [interrogate](interrogate/SKILL.md) — adversaries in their own worktrees try to break a change or design, and only findings proven by a rerun command survive; reports intent, verified findings with command and output, and dropped counts.
- [maintain-verification-skill](maintain-verification-skill/SKILL.md) — keep a project's verify skill and feature map honest with parallel read-only source readers per feature and one live pass over every feature, ending clean, changed (one PR of proven corrections), or blocked.
- [no-comments](no-comments/SKILL.md) — pre-PR comment hygiene: strip unjustified comments from the scoped diff, fix accepted root-cause flags, and offer encodings for claimed constraints.
- [pr-comments](pr-comments/SKILL.md) — turn review findings into concise, inline-first PR comments and submit them as one GitHub review; brevity-first, with a human-owned verdict.
- [principle-attack-the-premise](principle-attack-the-premise/SKILL.md) — when fixes built on one belief keep failing, write the premise down and test it directly before writing another fix that assumes it.
- [principle-boundary-discipline](principle-boundary-discipline/SKILL.md) — concentrate validation, type narrowing, and error handling at system boundaries, trust internal types, and keep business logic in pure functions behind a thin framework shell.
- [principle-build-the-lever](principle-build-the-lever/SKILL.md) — build the tool that does or proves the work (codemod, script, generator, or a skill subagents follow) instead of working by hand, so a reviewer can rerun it.
- [principle-encode-lessons-in-structure](principle-encode-lessons-in-structure/SKILL.md) — turn a recurring instruction or correction into structure (a lint, type, metadata flag, runtime check, or script) instead of more text.
- [principle-exhaust-the-design-space](principle-exhaust-the-design-space/SKILL.md) — build 2 to 3 competing prototypes and compare them side by side before committing to a novel UI, architecture, or product design.
- [principle-experience-first](principle-experience-first/SKILL.md) — when implementation convenience conflicts with user delight, choose delight, and ship fewer polished features over more rough ones.
- [principle-explain-the-number](principle-explain-the-number/SKILL.md) — before trusting a measured number, name what limits it and rule out errors, skipped or cached work, an untuned side, and noise.
- [principle-fix-root-causes](principle-fix-root-causes/SKILL.md) — trace each symptom to the first place the system went wrong and fix it there; a guard is a fix only when the state it handles is legitimate.
- [principle-foundational-thinking](principle-foundational-thinking/SKILL.md) — get the data structures right before writing logic: settle core types and access patterns, lay scaffold before features, and isolate shared state.
- [principle-guard-the-context-window](principle-guard-the-context-window/SKILL.md) — keep the main thread's context small: route bulk work to subagents, keep their summaries, and size phases so no context overflows mid-task.
- [principle-laziness-protocol](principle-laziness-protocol/SKILL.md) — bias toward deletion and the smallest change that solves the problem, with one source of truth per repeated decision and no layers that remove no real complexity.
- [principle-make-operations-idempotent](principle-make-operations-idempotent/SKILL.md) — design state-mutating operations to converge to the same end state however many times they run and wherever a previous run stopped.
- [principle-migrate-callers-then-delete-legacy-apis](principle-migrate-callers-then-delete-legacy-apis/SKILL.md) — migrate every caller to a new internal API and delete the old one in the same wave, with no compatibility layers.
- [principle-minimize-reader-load](principle-minimize-reader-load/SKILL.md) — treat maintainability as the work a reader must do: count layers and hidden state, collapse one-caller wrappers, and shrink mutable scope.
- [principle-model-the-domain](principle-model-the-domain/SKILL.md) — encode the domain in a data structure (state machine, typed model, registry, reducer) so invalid states become unrepresentable and branches disappear.
- [principle-never-block-on-the-human](principle-never-block-on-the-human/SKILL.md) — do reversible work without asking and let the human course-correct after the fact; irreversible actions and product direction still go to the human.
- [principle-outcome-oriented-execution](principle-outcome-oriented-execution/SKILL.md) — optimize a planned rewrite or migration for its verifiable end state, and keep no throwaway compatibility code alive between phases.
- [principle-prove-it-works](principle-prove-it-works/SKILL.md) — verify every output against the real artifact on the real surface, not a proxy, a self-report, or "it compiles".
- [principle-redesign-from-first-principles](principle-redesign-from-first-principles/SKILL.md) — redesign as if a new requirement had been a foundational assumption from the start, instead of bolting it on.
- [principle-separate-before-serializing-shared-state](principle-separate-before-serializing-shared-state/SKILL.md) — give each concurrent actor its own file, key, branch, or state directory and merge at the read boundary before serializing access to shared state.
- [principle-sequence-verifiable-units](principle-sequence-verifiable-units/SKILL.md) — break work into small units that each end in a verifiable state, check each before the next, and order commits and PRs so the sequence proves itself.
- [principle-subtract-before-you-add](principle-subtract-before-you-add/SKILL.md) — delete dead code, redundant validators, and stub references first, then build on the simpler base.
- [principle-test-behavior-not-implementation](principle-test-behavior-not-implementation/SKILL.md) — assert what the code's users can observe, and keep a test only if it catches a behavior-breaking edit and survives an internals-only edit.
- [principle-type-system-discipline](principle-type-system-discipline/SKILL.md) — make the compiler reject impossible states: illegal states unrepresentable, branded primitives, parsing at boundaries, exhaustive variants, and schema-derived types.
- [principles](principles/SKILL.md) — index of the `principle-*` leaf skills, autonomy pause lines, and the session-gates package that [cortex](cortex/SKILL.md) loads.
- [prototype](prototype/SKILL.md) — build a throwaway prototype (runnable terminal app or toggleable UI variations) to flesh out a design before committing.
- [shipping](shipping/SKILL.md) — independently verify then land contiguous merge-ready PRs bottom-up, with forge-aware merge hygiene; on GitHub, watch the run with babysit's queued `watch-pr` until it reports `COMPLETE`.
- [swarm](swarm/SKILL.md) — fan out N parallel workers (coverage, races, gauntlets, or multi-lens review), aggregate, and report; hand review findings to workshop-findings or pr-comments.
- [thermo-nuclear-code-quality-review](thermo-nuclear-code-quality-review/SKILL.md) — an extremely strict, maintainability-only review for abstraction quality, giant files, and spaghetti conditions, run only when asked for by name or for that bar.
- [thermo-nuclear-refactor](thermo-nuclear-refactor/SKILL.md) — full-scale refactoring of the whole system only: multi-agent discovery, cross-module tracing, and independent verification; show coverage, propose refactorings, and implement only accepted proposals. A focused refactor follows the cortex [Refactor playbook](cortex/playbooks/refactor.md).
- [unslop](unslop/SKILL.md) — strip AI tells and filler from replies, PR/commit text, docs, and other session prose, by numbered rules other skills cite by id.
- [why](why/SKILL.md) — investigate why code is shaped the way it is: build a git/PR code anchor, query each connected evidence category in parallel (issue tracker, docs, chat, observability, error tracking, analytics), and return a cited, confidence-tiered answer in chat.
- [workshop-findings](workshop-findings/SKILL.md) — walk review findings one at a time and decide the best fix for each, grill-me style, then hand a clean decision list to pr-comments.
