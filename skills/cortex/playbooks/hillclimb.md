### Hillclimb

**You own the metric and the experiment's integrity. Delegate the attempts, review each diff.** One change, one measurement, keep or revert. Never stack untested changes, and never claim a win from code inspection (the [Prove It Works](../../principles/prove-it-works.md) principle).

1. Ground the workload and the architecture. Read and follow [`how`](../../how/SKILL.md) over the target. Name the workload dimensions that can move the result (data size, history, state, concurrency), and pick a case that reproduces the user's complaint. If no case reproduces it, fix the repro before you climb. Fix one metric, the direction that counts as better, and a stop predicate that pairs a target with a floor on attempts, such as "at least 50% better than baseline and at least 10 iterations". Use the user's numbers, or the workload and target a [Perf issue](perf-issue.md) escalation carries. If you have none, pick them, state them in your first message, and proceed.
2. Build the measurement harness, prove it is sensitive, then freeze it (the [Build the Lever](../../principles/build-the-lever.md) principle). The target case must reproduce the symptom, and easier cases must separate from it. If they do not, revise the workload or the metric. Read and follow [`benchmark-checklist`](../../benchmark-checklist/SKILL.md) to vet the harness before you freeze it. The frozen harness is one command that prints the metric as a median over enough runs to clear the noise, plus its error count and a count of the work done. Commit it as the first commit of the stack. Record the baseline and a green run of the regression gate (the tests that must keep passing) before any change.
3. Read and follow the decision-trail mode of [`handoff`](../../handoff/SKILL.md) for the attempt log, one row per attempt. Its columns are `ts`, `phase` (the attempt id, or `start`), hypothesis, change, before, after, delta, tests, verdict (kept or reverted), and note. Read it before each attempt.
4. Ground each hypothesis in the step 1 model, so it names a mechanism ("defer X off the boot path because it blocks first paint"), not "try memoizing something". For a perf metric, order hypotheses by the mantras in step 2 of the [Perf issue](perf-issue.md) playbook, and ignore that step's stop rule.
5. Loop, one hypothesis per iteration:
   - Hand the change to a subagent with a tight scope (the [Guard the Context Window](../../principles/guard-the-context-window.md) principle). Independent hypotheses may build in parallel, each in its own worktree (the [Separate Before Serializing Shared State](../../principles/separate-before-serializing-shared-state.md) principle). Measure them one at a time, and measure again after you combine two wins.
   - Measure before and after with the frozen harness, and run the regression gate. Keep the change only when the metric moves past noise and the gate stays green. Otherwise revert it in full.
   - Commit each kept change on its own, staging only its files (`git add <files>`, never `-A`). Log the row either way.
   - If the run is unattended, take only the wake mechanism from the [Autonomous run](autonomous-run.md) playbook.
6. Push past plateaus, and stop only on the predicate. After several rejects in a row, pivot category, combine near-misses, re-read the source, or try something more radical. Correctness and simplicity outrank the number. Revert a win that breaks behavior, even when the gate is green, and keep a simplification that holds the metric (the [Laziness Protocol](../../principles/laziness-protocol.md) principle). Never relax the predicate. If the ideas run out or you are blocked before it is met, stop and report the gap instead of spinning. If no outer playbook owns this run, run the end-of-run trail audit and cross-model review from the decision-trail mode of [`handoff`](../../handoff/SKILL.md).
7. Run [Opening a PR](opening-a-pr.md) with the harness commit first and the kept commits in the order they landed.

**Reply:** the metric and target, baseline to final with the percent delta, iterations run (kept vs reverted), each kept change on one line, the attempt-log path, and the best idea you would try next.
