### Refactoring

**You own the contract. The structure changes. The behavior does not.** A missing feature or a real bug found on the way splits out to [Feature](feature.md) or [Bug fix](bug-fix.md), and the structural change ships first against the pin. A redesign that changes behavior is a Feature. Name it and route there.

1. Pin the behavior contract before any structure moves. Read and follow [`how`](../../how/SKILL.md) over the affected subsystem, then write a characterization test, snapshot, or equivalence harness that captures current behavior. Per [Test Behavior, Not Implementation](../../principles/test-behavior-not-implementation.md), the pin goes red when behavior breaks and stays green when only internals change. Rewrite existing tests that pin internals to the contract now, not mid-move. Type check and lint are not a pin.
2. Name the target shape. It is the structure the code is missing per [Model the Domain](../../principles/model-the-domain.md), and the module layout, types, and call graph you would build today per [Redesign from First Principles](../../principles/redesign-from-first-principles.md). The reshape must delete branches or invalid states, not add indirection.
3. If the target crosses a function boundary, read and follow phases A and B of [`architect`](../../architect/SKILL.md) to sketch it, with the step 1 explanation as phase A's grounding. Then continue at step 4, not at architect's phase D.
4. Subtract first, per [Subtract Before You Add](../../principles/subtract-before-you-add.md). Delete dead code, collapse one-caller wrappers, drop redundant validators, and remove orphan references before the new shape lands. Before you drop a guard or validator whose reason is unclear, read and follow [`why`](../../why/SKILL.md) on it.
5. Move in small steps, each keeping the pin green. Make renames and mechanical moves with a codemod or script per [Build the Lever](../../principles/build-the-lever.md). Delegate edits a script cannot make to a subagent with a specific scope (file paths, the names being moved, the behavior to hold). For an internal API reshape, migrate every caller and delete the old API in the same wave per [Migrate Callers Then Delete Legacy APIs](../../principles/migrate-callers-then-delete-legacy-apis.md), with no shims or parallel paths. After each rename, search the whole repo for the old name, strings, docs, and back-references included, and account for every remaining hit.
6. Prove behavior is unchanged on the real artifact per [Prove It Works](../../principles/prove-it-works.md). Rerun the pin. For a larger reshape, add an equivalence check: a script that diffs old against new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface via the repo's `verify-*` skill.
7. Keep only what lowers reader load per [Minimize Reader Load](../../principles/minimize-reader-load.md). Spawn a subagent that reads and follows [`thermo-nuclear-code-quality-review`](../../thermo-nuclear-code-quality-review/SKILL.md) on the diff, as the independent judge. Apply or revert its findings inside the target shape here, and split out findings outside it per the rule above step 1. Revert any part that does not lower reader load, speculative cleanup that "might help" included, per [Laziness Protocol](../../principles/laziness-protocol.md).
8. Commit the subtraction, then the reshape, then any follow-on cleanup, each green on its own per [Sequence Work into Verifiable Units](../../principles/sequence-verifiable-units.md). Run [Opening a PR](opening-a-pr.md).

**Reply:** the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta and the reviewer's verdict, what shipped and what got reverted. No new behavior.
